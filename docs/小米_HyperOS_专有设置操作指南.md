# 小米 / HyperOS 专有设置操作指南

## 1. 文档用途

本文用于整理“拉钩守护”在小米、Redmi、POCO 手机上需要人工完成的品牌专有设置，可直接作为后续用户说明书的小米章节底稿。

本文把两类权限严格分开：

- **Android 通用权限**：无障碍、悬浮窗、使用情况访问权限、忽略 Android 电池优化。应用通常可以读取真实系统状态。
- **小米 / HyperOS 专有设置**：后台自启动、小米省电策略、后台弹出界面、最近任务锁定。普通第三方应用通常不能可靠读取，也不能替用户自动授权。

当前操作路径已在以下设备环境中核对：

```text
设备：Redmi 23049RAD8C
Android：15
HyperOS：3.0.5.0.VMRCNXM
应用名称：拉钩守护
```

不同机型、系统地区和 HyperOS 版本的菜单名称可能略有差异。如果找不到同名入口，可在系统设置中搜索“自启动”“无限制”“后台弹出”或“无障碍”。

## 2. 推荐配置顺序

建议严格按以下顺序配置：

1. 授予悬浮窗权限；
2. 授予使用情况访问权限；
3. 允许忽略 Android 电池优化；
4. 开启小米“后台自启动”；
5. 将小米“省电策略”设为“无限制”；
6. 按实际需要允许“后台弹出界面”；
7. 在最近任务中锁定“拉钩守护”；
8. **最后开启无障碍服务**；
9. 返回“拉钩守护”，确认权限页显示无障碍服务运行正常。

把无障碍放在最后，是因为小米“手机管家 / 应用信息”中的“结束运行”及部分会停止应用的管理操作，可能同时让无障碍服务退出并从启用列表中消失。以后如果重新调整小米专有设置，也应在操作结束后再次检查无障碍。

## 3. 后台自启动

### 3.1 设置方法

常用路径：

```text
系统设置
  → 应用
  → 权限管理
  → 后台自启动
  → 找到“拉钩守护”
  → 开启
```

部分机型也可从以下入口进入：

```text
长按“拉钩守护”桌面图标
  → 应用信息
  → 自启动 / 后台自启动
  → 允许
```

### 3.2 作用

开启后，HyperOS 才允许应用在开机、系统回收进程或满足系统条件时进行后台恢复。小米官方说明中明确指出，第三方应用默认不可自启动，需要用户自行允许。

### 3.3 注意事项

- 这是小米品牌权限，不等同于 Android 的“允许后台运行”。
- 应用只能引导用户进入相关页面，不能替用户打开开关。
- 普通应用没有稳定的公开接口读取该开关，因此说明书不能承诺应用页面显示的值与小米系统页面百分之百一致。

## 4. 小米省电策略设为“无限制”

### 4.1 设置方法

常用路径：

```text
系统设置
  → 应用
  → 应用管理
  → 拉钩守护
  → 省电策略 / 电量消耗 / 电池
  → 无限制
```

如果上述路径名称不同，可在系统设置中搜索“省电策略”，或者进入“拉钩守护”的应用信息页查找“电量消耗”“电池”或“后台运行”。

### 4.2 作用

“无限制”用于降低 HyperOS 因省电策略冻结或终止后台服务的概率。小米官方对需要持续后台工作的应用同时建议：

- 关闭针对该应用的省电限制；
- 后台设置选择“无限制”；
- 允许应用自启动；
- 在后台锁定应用。

### 4.3 与 Android 电池优化的区别

以下两个设置不是一回事，应分别完成：

| 设置 | 所属层级 | 应用能否可靠检测 |
| --- | --- | --- |
| 忽略电池优化 | Android 通用机制 | 可以 |
| 省电策略“无限制” | 小米 / HyperOS 专有机制 | 通常不可以 |

应用显示“已忽略电池优化”，不代表小米省电策略已经设为“无限制”。

## 5. 后台弹出界面

### 5.1 设置方法

常见路径：

```text
长按“拉钩守护”桌面图标
  → 应用信息
  → 权限管理
  → 其他权限
  → 后台弹出界面
  → 允许
```

部分版本可能将它显示为“后台弹出页面”或放在“特殊权限”中。

### 5.2 作用与优先级

小米官方说明中，这项权限控制第三方应用能否从后台启动页面，默认状态为拒绝。

“拉钩守护”的普通应用拦截主要依靠无障碍与系统悬浮窗，并不应把“后台弹出界面”当作无障碍或悬浮窗的替代品。它主要用于增强部分后台恢复、告警或引导页面的可达性，优先级低于：

1. 无障碍；
2. 悬浮窗；
3. 后台自启动；
4. 小米省电策略“无限制”。

## 6. 最近任务锁定

### 6.1 设置方法

1. 打开“拉钩守护”；
2. 进入手机的最近任务页面；
3. 长按“拉钩守护”的任务卡片，或按当前系统手势下拉任务卡片；
4. 点击锁形图标；
5. 确认任务卡片上出现锁定标记。

不同小米桌面版本可能采用“长按后点锁”或“下拉卡片上锁”两种交互。

### 6.2 作用

最近任务锁定用于降低用户点击“一键清理”时应用被清除的概率。它不能保证进程永远不被系统终止，也不能代替后台自启动或省电策略“无限制”。

普通第三方应用没有公开、稳定的接口替用户锁定最近任务，也无法可靠读取桌面上的锁定状态，只能由用户人工确认锁形标记。

## 7. 无障碍服务

### 7.1 设置方法

常见路径：

```text
系统设置
  → 更多设置
  → 无障碍
  → 已下载的应用 / 更多已下载的服务
  → 拉钩守护
  → 开启
```

也可以从“拉钩守护”的权限配置向导点击无障碍项目进入系统页面。

### 7.2 不能只看一个开关

判断无障碍是否真正工作，需要同时满足：

1. 系统启用列表中包含“拉钩守护”；
2. 系统已经实际绑定 `GuardAccessibilityService`；
3. 应用能够持续收到服务心跳。

手机的总无障碍开关显示为开启，只能说明系统中至少有一个无障碍服务启用，不能证明“拉钩守护”正在运行。

### 7.3 调整小米设置后的复查要求

如果完成小米应用信息页操作后出现以下任一情况，应重新开启无障碍：

- “拉钩守护”的无障碍开关变为关闭；
- 应用显示“已配置但未运行”；
- 应用显示无障碍心跳异常；
- 拦截功能突然完全失效。

恢复时应先关闭“拉钩守护”无障碍开关，再重新打开，并返回应用确认运行状态。

## 8. 悬浮窗、使用情况访问和 Android 电池优化

这三项属于 Android 通用权限，不是小米专有设置，但仍是完整配置的必要部分：

| 权限 | 用途 | 应用能否读取真实状态 |
| --- | --- | --- |
| 悬浮窗 | 显示全屏遮蔽层和降级保护页 | 可以 |
| 使用情况访问 | 统计前台应用和使用时长 | 可以 |
| 忽略电池优化 | 降低 Android Doze 对保活的影响 | 可以 |

即使这三项全部显示正常，也不能推导出“后台自启动”“小米无限制”“后台弹出界面”和“最近任务锁定”已经完成。

## 9. 权限检测与设置能力边界

| 项目 | 应用可可靠检测 | 应用可自动设置 | 用户是否必须手工确认 |
| --- | --- | --- | --- |
| 无障碍配置 | 可以 | 不可以 | 是 |
| 无障碍实际绑定与心跳 | 可以 | 系统是否重绑不受应用完全控制 | 异常时需要 |
| 悬浮窗 | 可以 | 不可以 | 是 |
| 使用情况访问 | 可以 | 不可以 | 是 |
| 忽略 Android 电池优化 | 可以 | 只能发起系统申请 | 是 |
| 小米后台自启动 | 通常不可以 | 不可以 | 是 |
| 小米省电策略“无限制” | 通常不可以 | 不可以 | 是 |
| 小米后台弹出界面 | 通常不可以 | 不可以 | 是 |
| 小米最近任务锁定 | 不可以 | 不可以 | 是 |

因此，产品页面后续如果展示小米专有项目，应使用“请确认已设置”“需要人工核对”等措辞，不能把用户曾经点击过“已设置”当作实时系统权限状态。

## 10. 2026-07-25 本机无障碍掉线案例

本次真机检查确认，无障碍确实已经掉线，不是应用页面误报。

掉线后的实际状态为：

```text
系统总无障碍开关：开启
拉钩守护是否在 enabled_accessibility_services：否
拉钩守护是否在 Bound services：否
拉钩守护前台保活服务：应用重新打开后已运行
拉钩守护无障碍服务：未运行
```

03:05:58 的系统日志显示：

```text
ActivityManager: Force stopping com.kidsphoneguard
user=0: from process:com.miui.securitycenter

am_kill:
stop com.kidsphoneguard due to from process:com.miui.securitycenter

AutoRevokePermissionManager:
user revoke AS permission com.kidsphoneguard
```

同一时间点还记录到：

```text
前台页面：com.miui.securitycenter/
           com.miui.appmanager.ApplicationsDetailsActivity
页面标题：应用信息
操作来源：触摸事件
```

紧接着系统发送 `PACKAGE_RESTARTED`，并更新了 `enabled_accessibility_services`。本次没有新的 Java 崩溃记录，应用也没有在该时间点安装或升级。

由此可以确定：

1. 本次无障碍是真实关闭并解除绑定；
2. 直接触发者是小米手机管家的“应用信息”页面；
3. 触发链是停止应用，而不是应用自身崩溃或普通后台回收；
4. 日志没有记录被点击控件的文字，所以不能仅凭日志断言是用户直接点击了“结束运行”，还是该页面中的其他操作间接调用了停止应用。

这也是为什么说明书应要求：小米专有设置全部完成后再开启无障碍；以后只要重新进入应用信息页调整设置，都要再次检查无障碍运行状态。

## 12. 编写用户说明书时的推荐措辞

可直接采用以下提醒：

> 小米 / Redmi / POCO 手机还需要完成“后台自启动”“省电策略设为无限制”和“最近任务锁定”。这些属于小米系统专有设置，应用无法替您自动开启，也无法始终准确读取其状态。请先完成全部小米专有设置，最后再开启“拉钩守护”的无障碍服务。以后如重新调整应用信息页设置，请再次检查无障碍是否仍在运行。
