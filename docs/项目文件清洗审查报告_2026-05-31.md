## 六、新增发现（原始报告未覆盖）

### 6.1 Git 跟踪与忽略规则冲突

约 **40+** 个 C 类文件已被 Git 跟踪，但它们同时落在 `.gitignore` 规则范围内。这属于典型的"先跟踪后忽略"历史债务。清洗时必须执行 `git rm`，否则仅删除磁盘文件会在下次提交时留下死引用。

### 6.2 `observer/` 模块的源码已进入版本控制

虽然 `observer/` 未在 `settings.gradle.kts` 中注册（确认死代码），但其源码文件（约 16 个）确实被 Git 跟踪。这意味着该模块并非简单的未使用目录，而是有过提交历史的废弃代码。清理必须使用 `git rm -r observer/`。

### 6.3 `docs/` 目录存在"部分跟踪"现象

- **被跟踪**：`docs/plans/` 下 16 篇计划文档（B 类，应保留）。
- **未被跟踪**：`docs/01_*`、`docs/02_*`、`docs/03_*`、`docs/04_*`、`docs/掉权限分析问题分析/`（C 类，可直接删除）。
- **原因**：历史提交时可能仅 `add` 了 plans 目录，其余目录从未进入版本控制。
