# 设置保护策略决策矩阵与测试计划

日期：2026-07-11
关联问题：ISS-002、ISS-015

## 背景与边界

`ProtectedSettingsPolicy` 负责在系统设置、权限页和厂商管家页面中区分“仅观察”“拦截危险动作”“拦截整个页面”和“放行”。当前策略直接依赖 `SettingsManager`，而核心优先级没有 JVM 单元测试保护；这会使后续根据真机日志补充 ROM 关键词时容易改变既有拦截边界。

本次不凭静态猜测新增厂商页面包名或关键词。OPPO/vivo/Huawei/Honor 的实际页面覆盖仍须以真机回归和日志为准。

## 实施步骤

1. 将不依赖 Android 运行时的策略判定提取为内部纯逻辑，输入为页面快照、品牌规则和运行时开关状态；保留 `ProtectedSettingsPolicy` 作为读取 `SettingsManager` 并调用该逻辑的门面。
2. 保持现有判定优先级与行为不变，重点保护：全局解锁放行、守护能力页的危险点击优先拦截、设置向导访问放行、SystemUI 瞬态页放行，以及目标应用相关页面的 `BLOCK_ACTION` / `BLOCK_PAGE` / `OBSERVE` 分级。
3. 添加 JVM 测试，覆盖上述优先级和每种决策结果，并验证品牌规则中已有的包名分类不被重构改变。
4. 运行 `testDebugUnitTest` 与 `assembleDebug`；无真机时只报告静态和 JVM 验证结果，不声称设备行为已验证。
5. 更新 `docs/ISSUES.md` 的进展记录：ISS-002 保持进行中，注明本次完成的可测试化与决策矩阵保护；ISS-015 记录新增策略覆盖，剩余端到端与设备测试范围。

## 验收标准

- 重构前后，既有 `ProtectedSettingsPolicy.evaluate()` 的输入输出语义保持一致。
- 单测能稳定证明四种决策和关键优先级。
- Debug 单元测试和 Debug APK 构建均通过。
- 文档明确未完成的真机关键词/响应速度验证，不将其误记为已完成。
